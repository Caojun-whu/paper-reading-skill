# 资料获取回归验收（Codex 人工评测）

本表用于验证 **AI 优先工具选择 ≠ 省略完整精读材料准备**。这些是预期行为，不是已完成的自动测试。不要将外部链接可打开误判为已经成功下载。

## 案例 A：Omni（arXiv:2508.06584）——来自真实测试的回归用例

输入：`https://arxiv.org/pdf/2508.06584，请为我讲解这篇论文`。有可写项目目录，按六站开始。

已核实的公开入口：
- PDF / TeX Source：[arXiv:2508.06584](https://arxiv.org/abs/2508.06584)，提供 **TeX Source** 链接。
- Omni 官方模型代码：[Figshare 分享页](https://figshare.com/s/3a4ebcb6c255e40d76f5)（论文 §7 明确列出）。
- LLM 实验代码：[Figshare 分享页](https://figshare.com/s/f45389595a58fcb669dd)（论文 §7 明确列出）。

**验收标准**
1. 保存 PDF 并验证文件有效；无须强制执行 Python 脚本。
2. 识别 arXiv 页面提供的 TeX Source，**实际尝试下载**并检查解包得到的 `.tex`；下载工具无法处理 gzip/tar 时改用适合的文件工具或记录具体错误，不能因为网页已有 HTML 就忽略。
3. 从论文 §7 识别 Figshare 为**作者明确提供的代码源**。尝试找到实际代码文件下载地址并保存到 `code/`；不能把 Figshare 当 GitHub `git clone`，也不应将网页 HTML 当作代码。
4. 如果 Figshare 返回 403/其他访问限制，明确记录两个代码入口、访问结果与受限原因，**不得标记已保存**，也不应盲目宣称“代码未公开”。
5. **提取全篇图表，而非只有图 1**：遍历 PDF 正文和附录中的全部 Figure / Table（先查 caption 编号，再核对原 PDF），分别保存到 `Omni/figures/` 和 `Omni/tables/`；创建两个 `index.md`，逐项记录原编号、caption、PDF 页码、独立文件路径和 `verified` / `needs-review` / `failed` 状态。所有多子图、表头、数值必须对照原页核验；裁剪错误时重裁。核对索引中的预期数、保存数、核验数及缺失项，不能用 `_contact.png` 的前 12 个候选代替全文覆盖。
6. 第一站答复同时给出 PDF / LaTeX / 官方代码 / 图表的**独立状态**（成功保存、未公开、无法访问、下载失败或待核实），图表报告预期数/已核验数，笔记中也有对应记录；失败可继续当前站。
7. 没有执行第三方代码、没有下载训练权重、没有覆盖已有笔记或人工编辑的裁图。

**回归失败示例**：只保存 `paper.pdf`、`paper.txt`、图 1 和笔记，却没有 TeX Source 获取尝试；或只找到 Figshare 链接未尝试下载且未记录失败原因；或只裁第一站用的图 1、没有完整 Figure/Table 清单、单独表格文件及逐项核验结果。

## 案例 B：重点理解一个公式，但仍须六站精读

输入：“使用 paper-reading 精读这篇论文，我尤其想理解式（3）”。

**验收**：首次阅读仍在①站前尝试保存 PDF、公开 TeX 源码与经确认的官方代码并记录状态；随后按①至⑥推进。在对应站（通常④）重点解释式（3）和数值例子；不得因请求特别关注一个公式而跳过资料获取或建立单点问答快捷模式。

## 案例 C：没有公开源文件或没有可核实的官方代码

选择一篇只有 PDF 或作者未公开实现的论文，请求完整六站精读。

**验收**：尝试检查 TeX Source 和正文/作者代码声明；记录 `unavailable`、`unverified` 或 `failed` 的真实原因，不编造代码地址，不为缺失材料生成空目录假装齐全，继续有证据支持的阅读。

## 评测记录

每次人工测试至少保存：输入提示、Codex 版本与工具环境、各资源链接、工具调用记录、实际文件列表、PDF/LaTeX/代码状态、`figures/index.md`、`tables/index.md`、图表预期/核验数量、图表裁剪复核结果、错误和第一站回复。只有**完成真实端到端运行**才能填写通过/失败；本文件本身不构成执行证明。
