# 六站精读：教学细则（适应不同论文类型）

**核心顺序：① 动机 → ② 架构 → ③ 数据与监督 → ④ 训练与优化 → ⑤ 推理与信息流 → ⑥ 案例与证据检验。**

这六站是**理解目标，不是所有论文都必须逐项填满的模板**。开始前先判断论文类型：算法/深度学习、理论、系统、数据集或综述。各站允许按任务替换内容、调整局部顺序、合并不适用部分；应向用户简要说明调整原因。用户只问某个问题时直接回答，不强制从①开始。

完整精读需要理解原文、核对图表和关键证据；但**只获取当前站所需要的材料**，避免为了开始一站而无差别下载所有附件。讲完当前站后暂停，用户说“继续”才推进；用户一次要求多站、跳站或快读时以用户意图为准。

## ① 研究动机：为什么需要这个方法？

- 说明**具体研究问题**、常见旧方法、旧方法真正无法解决的地方，以及作者的关键假设。用与任务有关的场景说明问题，避免只改写摘要中的贡献宣称。
- 区分作者声称的不足与文献/实验真正能证明的不足；有帮助时查看并展示原论文 teaser 图。
- **完成标准**：用户能解释“什么问题、旧方法哪里不够、作者如何破局”。

## ② 模型架构：作者提出了什么？（静态视角）

- **先查看论文总览图**，在界面允许时展示，否则精确定位 PDF 页码与图号；未经实际查看不能宣称“图中显示”。
- 先讲**输入与输出**，再讲模块、模块职责、连接关系、初始化和可训练部分，以及为什么采用这种设计而非简单替代方案。
- 如有经核实的官方代码，可静态核对模块定义和接口。
- **本站只解释“有哪些部件、为什么这样连接”**；不要提前逐张量完整跑一次前向传播（留给⑤），也不展开全部损失（留给④）。
- **完成标准**：用户能根据原图描述主要模块及各自功能。

## ③ 数据与监督：模型究竟看到什么？

- 交代数据来源、采集/构造方式、规模、训练/验证/测试划分、预处理及可能的数据泄漏风险。
- 核心是**一条样本**：字段、类型、shape、单位、时空尺度、示例值、标签/目标/正负样本关系、样本被组织为输入的方式。
- 说明每类监督信号从哪里来（人工标签、自动构造、对比学习、无监督信号等），使用户在④看到 loss 符号时已知道它对应什么。
- 优先核对数据定义、公开真实样例及经核实的 dataset/transform 代码；没有真实数值时清晰标记“示意”，不要冒充真实数据。
- **本站回答“数据和标签是什么”**；不要抢先推导优化公式（留给④）。
- **完成标准**：能描述一条样本、监督来源和模型会接收哪些字段。

## ④ 训练与优化：模型如何学会这个能力？

- 先用自然语言说明目标，再讲主要 loss、训练阶段、冻结与更新参数、采样/批次构造、重要超参数及训练与推理差别。
- 承接③已有的样本和监督信号，不再从头重复整个数据集介绍。
- 关键公式按**原式 → 符号/shape → 计算步骤 → 直觉 → 小规模数值例子**解释。论文没给出的值不编造。
- 有官方代码时静态核对 loss、优化器、配置和参数更新；发现论文与代码不一致时分别说明，不擅自消除冲突。
- **完成标准**：用户能说出优化了什么、监督来自哪里、参数怎样更新。

## ⑤ 推理与信息流：模型运行时发生什么？（动态视角）

- 以一个实际输入或明示的示意输入，沿**输入 → 预处理 → 编码/模块调用 → 中间张量 → 预测 → 输出**追踪执行顺序。
- 优先核对具体模块调用、可确认的 shape、循环/缓存/状态变化；区分训练路径与推理路径。
- **本站关注“如何运行”**，仅简要引用②的模块职责，不重复静态架构；也不在此站完成一整套逐数值手算（留给⑥）。
- 不知道的维度或代码细节明确指出未知，不用抽象口号掩盖缺口。
- **完成标准**：能跟随一条输入说出关键中间量与生成输出的顺序。

## ⑥ 案例与证据检验：它怎样算、真的有效吗？

**同一站内分为 A（掌握方法）和 B（检查证据）。A 为主，B 保持精炼；内容很多时可以在第⑥站内继续多轮，不新增第七站。**

### A. 完整案例推演（主任务）

- 优先使用论文公开且能核实的真实示例；不足时用**明确标注“示意”的玩具数据**，缩小维度但保留实际步骤。
- 按真实执行顺序走完输入、关键计算与状态、对应公式/模块/代码位置、最终输出，并映射回真实规模。
- 对循环或迭代（如适用）至少演示两次关键步骤；不要用粘贴大段源码代替推演。

### B. 实验证据与局限检验（简短但必须触及）

- 选出**最直接检验作者核心主张的结果**：任务、数据集、评估指标、强基线及提升幅度（仅引用论文真实数据），不要机械复述所有表格。
- 问：消融研究能否支持关键模块的贡献？是否控制了算力、参数量、数据规模等因素？是否存在明显代价、失败场景、泛化限制或实验设计缺口？
- 明确区分**作者的解释**、**实验实际支持的结论**和**【分析】批判性判断**。论文缺少消融或对比时写“未提供/尚未核实”，不代写证据。
- 理论论文可用证明前提和反例边界替代实验；系统论文看吞吐/延迟/资源和工作负载；数据集论文看质量、偏差与评测协议；综述看比较覆盖和论据质量。

- **完成标准**：用户能手动走通一个简化案例，并指出至少一条有证据支持的有效性结论及一项局限或尚未证实的问题。

## 论文类型自适应（仍保留六站的理解目标）

| 论文类型 | 如何调整中间站与第⑥站 |
| --- | --- |
| **算法/深度学习** | 默认采用以上六站；③先样本/监督、④再 loss/训练、⑤运行时信息流。 |
| **理论/数学** | ②改为核心定义与理论框架，③聚焦问题设定与假设，④改为关键定理/证明思路，⑤改为推导或算法执行逻辑；⑥使用小反例/证明边界及条件检验。 |
| **系统/工程** | ②为系统组件，③为工作负载与输入约束，④为设计决策/优化机制，⑤为请求与状态流；⑥为具体请求案例与性能、资源及基线证据。 |
| **数据集/基准** | ②为数据集/评测框架，③重点展开采集、标注与划分，④为质量控制/评测协议，⑤为样本进入评测的过程；⑥为样例与偏差、可靠性检验。 |
| **综述/Survey** | ②为分类框架，③为文献筛选范围，④为比较维度和综合方法，⑤为技术演变与方法关系；⑥以代表性案例和证据覆盖/遗漏为主。 |

**不适用时不要编造“训练损失”或“模型张量”**：简要说明对应内容为何改为理论证明、系统优化或评测协议，仍保持教学流畅。若为了理解需要局部调整③和②等顺序，可调整并告知用户，不必每次机械跳转。

## 互动、来源与记录

- 每轮仅讲当前站；收尾一句回顾、一句下一站预告。用户说“继续/下一步”才推进；站内问题复杂时可分多轮，用户要求跳站或一次快读多站时遵从用户。
- “没看懂”时改用真实或示意的小数值、极小例子和简单替代方案比较，避免只把原答案讲得更长。
- 图片必须实际查看，无法展示时提供 PDF 页码、图号；候选裁图需核对原页。
- 事实区分 **【论文】**、**【官方代码】**、**【分析】**；关键数据给出 PDF 页/公式/表/图或代码位置。用户可随时要求深入实验、创新性、局限或跨论文比较。
- 能写文件时，按 `references/notes-template.md` 增量更新 `精读笔记.md` 的当前站、结论、问答和下一步；不可写时说明没有持久化。**旧版笔记若③是训练、④是数据，应按标题/内容识别旧进度，不能单凭数字强制重标或覆盖旧笔记。**
