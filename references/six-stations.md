# 六站精读：教学细则

本文件按当前站加载使用。**先核实足以支持当前解释的论文材料，再讲解；每轮只推进一站。** 不必为了回答局部问题先完整执行六站。

## ① 动机：为什么做？

说明具体研究问题、常见旧方法的处理方式、真正的困难，以及作者提出的关键假设。尽量给出与论文任务有关的真实场景，避免把摘要的宣传语换句话说一遍。

结束时，用户应能回答：**要解决什么问题？旧方法为什么不够？作者准备怎样破局？** 如果 teaser 图确实有帮助，先查看原 PDF 并按图讲解。

## ② 架构：模型怎么设计？

**先展示或准确定位原论文总览图，再沿图讲解**。先说清输入、输出，再按数据流解释重要模块的输入/输出、作用、初始化、哪些参数可训练，以及模块的连接关系。

对非显然设计回答“为什么这样做，而非更简单的方法”；若有经核实的官方代码，静态检查关键模块接口与 `forward`，核对图中数据流。此站不必提前展开全部损失函数。

若无法查看原图，须明确说明并给出精确图号和 PDF 页码，不能假装看到了图。

## ③ 训练：究竟学什么？

先用一句自然语言说明训练目标，然后解释监督/自监督信号、正负样本构造、主要损失、各训练阶段、参数冻结/更新及重要超参数。

每个关键公式按以下顺序讲：

1. **原式**：尽可能与论文核对；
2. **符号与形状**：解释各变量与维度；
3. **计算步骤**：说明它实际怎样计算；
4. **直觉**：为什么要优化它；
5. **玩具数值例子**：缩小维度演示一次。

如有经核实的官方代码，优先静态核对 loss、训练配置与参数更新；论文与代码不一致时分别报告，不自行“补齐”差别。必要时区分训练与推理。

## ④ 数据：一条样本长什么样？

交代训练/验证/测试数据的来源、采集或构造方式、规模、划分和预处理。核心是**给出单条训练样本的字段、类型、shape、单位、空间或时间尺度，以及它怎样组织成模型输入**。

优先通过论文数据描述、公开真实样本、经核实的 dataset/transform 代码核对。拿不到真实样本时可提供小规模示意值，但必须显著标注“示意”，不可称作真实数据。

## ⑤ 信息流：输入怎样变成输出？

依据论文与经核实的代码（若有）沿实际顺序讲清：**输入 → 预处理 → 编码 → 中间张量 → 预测 → 输出**。

标注能确认的关键 shape、模块调用、循环、缓存或状态更新；区分训练和推理路径。可以用短文本流程图辅助，但不能用抽象术语替代具体数据流。

若论文和代码均未给出某个维度或中间计算，明确标记未知；不得推断后当成事实。

## ⑥ 具体案例：拿一条任务走完流程

优先使用论文公开的真实案例。没有完整可复核样本时，用显著标注为**示意**的小数据，逐步演示：

- 输入内容和组织形式；
- 预处理与各模块的关键数值/维度；
- 对应公式或可核实的代码位置；
- 输出及其含义；
- 玩具规模如何映射回论文的真实任务。

存在循环或迭代时，至少走两次有意义的步骤（如适用）。目标是让用户理解具体算法如何运作，不是粘贴大量源码。

## 每站的共同规则

- **讲完当前站即暂停**，用一句话总结本轮，再用一句话预告下一站。仅当用户说“继续/下一步”才推进；复杂站点可分多轮。
- 用户要求跳站、查实验、比较论文或追问某个公式时，直接回答，并说明阅读位置；不强行维持顺序。
- 用户反馈“没看懂”时，改变解释方式：真实/示意数字 → 极小玩具例子 → 与简单方案比较，避免机械重复。
- 实际查看图片后才可据图讲解；界面支持时展示，不能展示则给出 PDF 页码和图号。图片裁剪必须和原页核对。
- 对事实使用 **【论文】**、**【官方代码】**、**【分析】** 区分证据；对关键数值标明页码、公式、图表或代码位置。不要把作者的主张写成不容置疑的结论。
- 公式尽量正确渲染，若客户端显示有问题则使用可读的纯文本表达和数字例子。
- 有可写本地工作区时，在当前站结束后增量更新对应论文的 `精读笔记.md`（参考 `references/notes-template.md`）；没有写入能力时明确告知未持久化。
