# 第⑤站：交互式信息流 HTML 设计与验收指南

本指南供 Agent 在执行第⑤站时按需阅读；它不是固定 UI 模板；**默认必须呈现同一个可漫游的全景大画布，而非分栏控制台。****每篇论文独立设计表达方式，以讲透从原始数据到训练或推理结果的完整数据流、机制与维度为目的；不以某一条数据的单独案例演算为主线。** 最终交付写入 `<论文名称>/信息流与维度可视化.html`，而非把 Viewer 工程放进 Skill 仓库。

## 1. 先核实，再设计

1. **从原始数据入口开始**：对照论文正文、原始 LaTeX 和已核实的官方代码，核实原始数据的来源/格式、加载、解析、清洗、采样、预处理、增强、任务数据或 batch 组织，再提取模型计算和训练/推理末端的完整执行链、分支、张量名称和 shape，列出可定位的证据（页码、公式/图、代码文件/函数）。不能从现成的网络输入起步，也不要执行论文代码来“猜”结构。
2. 每个关键阶段至少明确**数据/张量输入 → 操作 → 输出**及其语义；解释原始数据如何形成样本/序列/图/批次，并记录 reshape、permute、split/merge heads、concat、pool、采样、时间循环、KV cache 等关键轴变化；不要只记录最后的维度。
3. 标记形状的证据级别：**确证**（论文/代码明确给出）、**可严格推导**（列出推导假设与计算）、**未知**（没有依据）。示意数值单独标记，不把示意变成事实。
4. **覆盖全流程**：训练路径（若存在）从数据准备、前向预测延伸至监督、loss、反向传播、参数更新及适用的循环/阶段；推理路径从原始输入到预处理、模型执行、循环/解码、后处理及最终任务结果。论文没有的环节不强加。可将细节折叠，但总览不准截断关键阶段，也不要求逐数值手算某一条数据。

## 2. 全景大图与 Vibe 式镜头叙事（P0，必须遵守）

**目标不是“做一个能点击的教程网页”，而是“一张会动的知识海报 / 一镜到底的论文信息流地图”。** 借鉴「Vibe 知识大赏」的代码动画与镜头节奏，但不复制固定视频画面、字体、音乐或配色；视觉语言由当前论文的实际计算机制决定。

**动手写 HTML 前，先在内部完成五项设计：** 原始数据入口、端到端主路径和真实分支/反馈线、最能表现数据变换的视觉隐喻、镜头沿路径穿行的顺序、证据与维度细节的收纳方式。**先确定真实拓扑，再做动画。**

**硬性布局要求：**

1. **唯一主场景**：整页以连续 SVG/Canvas/WebGL 等大画布为中心，不塞进小卡片或左右分栏。首次打开默认为 fit-to-overview，**同一屏能认出原始数据、关键处理阶段、核心模型、训练反馈和/或推理出口，以及它们的连接**。细节可以按层级折叠、通过 pan/zoom 观察；切勿为在首屏塞满所有文字而把节点缩小到无法阅读。
2. **画布拓扑不会因浏览过程消失**：所有重要主阶段同时占有空间；训练与推理若均存在，在同一幅图内共存，可突出一条并淡化另一条，但不可在切换路线时把一条替换成互不相关的新流程图。原始数据到模型输入的预处理、标签/监督信号、训练的 loss→反传→更新反馈线或推理末端的解码/后处理，都按真实机制连接。无相应步骤则不编造。
3. **让数据变形而不是单纯点亮盒子**：用有意义的视觉变换展示拆分、聚合、重新排列、分辨率变化、关系建图、注意力映射、反馈更新和迭代。使用流线、箭头、动态轨道与图例表达方向，动画必须能对应到输入/输出 shape 或状态变化；不允许漂浮粒子、闪烁边框代替机制解释。
4. **镜头穿行且保持空间记忆**：播放时镜头沿主路径平滑平移/缩放，聚焦当前阶段或局部展开；前后步只改变此画布的视角和高亮，用户可暂停、自由拖动、放大、返回全图。不能“每点一下刷新一张不同 SVG”或做成分页幻灯片。自动游览只是一种看法，不是强制观看条件。
5. **证据是第二层，不抢主画面**：关键名称、流向、数据形态和必要 shape 直接标在画布上；长解释、原始 LaTeX/PDF/代码出处、完整数据与维度流转表采用点击节点的浮层或默认收起的抽屉。必须可查证，但不应常驻大段文字与表格。控制条轻量、位置不遮挡主路径。
6. **审美有作品感但可读**：层次清晰的标题、大字关键节点、有限且有语义的强调色、留白/留黑、连贯转场与克制动效。画幅、色调、世界观由论文决定；不固定黑金、长卷或 3D。训练/推理及不同模态的色彩使用保持一致并有图例。高维张量 3D 仅为可选的局部投影，不是必须渲染成旋转立方体。

**明确判定为失败的反例：**

- 「标题/步骤按钮 → 左侧局部 SVG → 右侧说明卡 → 下方常驻大表格」的 Dashboard/教学控制台（本轮测试 HTML 的主要问题）。
- 按下一步切换为另一幅互不相连的图，用户缩小也无法看到整个系统的幻灯片式说明。
- 独立盒子/卡片拼盘，没有连续路径或真正的训练反馈；只能看文字才能理解数据如何流动。
- 固定 Vibe 配色模板、无意义闪光/旋转/粒子，不能对应一个真实变换；为了效果隐去未知尺寸或声称示意是真实值。

## 3. 视觉形式自由，但有明确的教学作用

按论文内容选择最清晰的表达组合，而非固定套用一种流程图：

- **CNN / ViT / 多尺度视觉**：分辨率、patch 与通道的动态变化；可以用可切换角度的特征图堆叠表达，清楚标注尺寸轴、stride 与下采样。
- **Transformer / Attention**：用 token 序列和 Q/K/V、注意力矩阵、head 拆分与合并的动画解释 shape 变化；不要把注意力动画误称为实际权重，除非有真实权重数据。
- **多模态 / 融合**：用平行的模态轨道、对齐位置、cross-attention Q/K/V 来源与融合点展示信息交换。
- **GNN / 时空模型**：显示图节点/边与消息传递轮次，或时间和空间两个轴的变化，避免把所有边都画成拥挤的线团。
- **生成、扩散、循环/检索模型**：通过时间轴、循环步进、状态/缓存更新展示迭代过程，按需演示两轮关键步骤。
- **非标准方法或非张量任务**：自主设计更适合其机制的二维过程图、空间坐标、状态机等；无意义的形状不得硬填。

**鼓励表现力**：用有语义的色彩、动效、分层景深、局部放大、过程对比、小型示意数据和自然语言注释让抽象计算可见；让模块输入与输出的变化能被“看见”，而不是旋转几个没有意义的方块。强制显示每种视觉编码的含义。若大小、长宽比、坐标或颜色并非真实数据比例，明确写“示意，不按比例”。对超过三维的张量展示选定轴的投影/切片，并始终保留**完整 shape 标签**。

## 4. 单文件、无需服务器、交互完整

- 生成一份能以 `file://` 直接打开的完整 HTML：样式写在 `<style>`，逻辑写在 `<script>`，形状/步骤/证据数据内嵌；无需 npm、构建工具、本地服务器或网络。**不能依赖 CDN、远程字体、外部图片、动态 import、fetch 本地 JSON 或远程 iframe。**
- 优先使用原生 HTML + CSS + SVG/Canvas；只有 3D 空间关系确实有助于理解时才用 Three.js/WebGL。采用库时须将可离线使用的库代码及必要许可声明一起合法地打包进同一个 HTML；做不到就退回原生实现，不得假称离线。
- **最小交互**：同一全景大图的总览、平移/缩放、返回总览、沿路径播放/暂停、前后步与重置；用户点击/键盘聚焦阶段在原图上高亮并展开局部，显示数据形式、输入/输出 shape、操作意义及论文/代码位置。可按需高亮训练或推理路径、调整速度和循环轮次；不要通过切换路线把另一条路径从总图删除。
- 页面中有可阅读的**数据与维度流转表**：涵盖原始数据、加载/组织、模型计算、训练更新与推理输出的实际阶段，列明数据结构、输入/输出 shape、语义、操作、来源及证据等级；但它应位于**默认收起的抽屉/详情层**，不应成为常驻下方大表或占据主画面。
- 中文为主，保留关键英文术语。兼顾桌面与窄屏；文字要清晰、对比度足够，提供 `prefers-reduced-motion` 或显式关闭动画的方式，基本操作可用键盘完成。渲染大规模图时应使用聚合、按需展开或抽样，并清楚标明抽样。
- **安全与来源**：不要把论文或仓库中的不可信字符串作为未经转义的 HTML/JS 执行；不运行论文模型/训练脚本，不注入外部跟踪或请求。交互示意图不等于论文原图：原始 Figure/Table 仍从 `source/` 与 LaTeX 索引核对，不截图论文 PDF，也不伪造实际激活/数值。

## 5. 完成前验证、续读与降级

- 检查 HTML 在目标路径确实存在；能使用浏览器测试时，**优先检查第一屏是否完整显示一张有连续连线的全景总图**，并试用同图平移缩放、镜头漫游、播放暂停、局部展开、训练/推理高亮、返回总览，以及证据抽屉，检查浏览器报错、离线资源、窄屏文字与动效减少功能。不能浏览器测试时做静态检查并**明确标注未实测**。
- **从原始数据入口到最终环节**逐段复查动画/分支/shape；检查训练路径是否覆盖适用的监督、损失、反传和更新，推理路径是否覆盖适用的解码与后处理；核验来源、未知项、示意比例及训练/推理差异。复杂模型可以分层折叠细节，但不得删去关键阶段冒充完整流程。
- 在 `精读笔记.md` 记录 HTML 的相对路径、所覆盖的模型版本、可视化设计选择、核验结果和待解决问题。续读优先复用已有文件；如已被用户修改，不直接覆盖，需另存版本或保护性备份。
- 若环境无法创建文件或无法达到离线单文件要求，**说明具体限制**，仍在对话中呈现可核验的步骤与维度表；不把静态截图或联网网页冒充已完成的独立 HTML。

## 6. 交付验收清单：P0 失败应重画，不是加按钮

- [ ] **首屏全景**：第一眼是一张完整连接的大图，而不是标题、步骤导航、局部 SVG、说明卡片和大表格。
- [ ] **连续路径**：从原始数据起点沿同一画布能顺着路径走到训练更新和/或最终推理输出；真实分支、共享部分、反馈和循环可辨。
- [ ] **单图镜头**：播放与前后步采用同图高亮、pan/zoom 和局部展开，不切换成独立的步骤页。
- [ ] **可解释变形**：至少主要阶段的结构/shape/状态改变可被图形和标注核验，不是只看光点跑动。
- [ ] **证据分层**：论文/官方代码/分析与完整维度表可按需展开，但默认不占主画面；未知、推断、示意标识清楚。
- [ ] **真实可用**：单文件离线直接打开、控件有效、总览可恢复、阅读顺畅；能测试则实测，否则如实说明限制。

**P1 加分项**：镜头节奏平滑、语义动画富有感染力、重点机制可原地放大展开、桌面/窄屏和键盘操作良好。P1 不能弥补 P0 缺陷。

**交付前最后自问**：缩小到总览，用户能不能在**同一张大图**上从原始数据一路沿线走到结尾？不能就重新设计画布；仅给 Dashboard 换深色、加粒子或平滑过渡不算修复。
