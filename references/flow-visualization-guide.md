# 第⑤站：交互式信息流 HTML 设计与验收指南

本指南供 Agent 在执行第⑤站时按需阅读；它不是固定 UI 模板。**每篇论文独立设计表达方式，以讲透从原始数据到训练或推理结果的完整数据流、机制与维度为目的；不以某一条数据的单独案例演算为主线。** 最终交付写入 `<论文名称>/信息流与维度可视化.html`，而非把 Viewer 工程放进 Skill 仓库。

## 1. 先核实，再设计

1. **从原始数据入口开始**：对照论文正文、原始 LaTeX 和已核实的官方代码，核实原始数据的来源/格式、加载、解析、清洗、采样、预处理、增强、任务数据或 batch 组织，再提取模型计算和训练/推理末端的完整执行链、分支、张量名称和 shape，列出可定位的证据（页码、公式/图、代码文件/函数）。不能从现成的网络输入起步，也不要执行论文代码来“猜”结构。
2. 每个关键阶段至少明确**数据/张量输入 → 操作 → 输出**及其语义；解释原始数据如何形成样本/序列/图/批次，并记录 reshape、permute、split/merge heads、concat、pool、采样、时间循环、KV cache 等关键轴变化；不要只记录最后的维度。
3. 标记形状的证据级别：**确证**（论文/代码明确给出）、**可严格推导**（列出推导假设与计算）、**未知**（没有依据）。示意数值单独标记，不把示意变成事实。
4. **覆盖全流程**：训练路径（若存在）从数据准备、前向预测延伸至监督、loss、反向传播、参数更新及适用的循环/阶段；推理路径从原始输入到预处理、模型执行、循环/解码、后处理及最终任务结果。论文没有的环节不强加。可将细节折叠，但总览不准截断关键阶段，也不要求逐数值手算某一条数据。

## 2. 视觉形式自由，但有明确的教学作用

按论文内容选择最清晰的表达组合，而非固定套用一种流程图：

- **CNN / ViT / 多尺度视觉**：分辨率、patch 与通道的动态变化；可以用可切换角度的特征图堆叠表达，清楚标注尺寸轴、stride 与下采样。
- **Transformer / Attention**：用 token 序列和 Q/K/V、注意力矩阵、head 拆分与合并的动画解释 shape 变化；不要把注意力动画误称为实际权重，除非有真实权重数据。
- **多模态 / 融合**：用平行的模态轨道、对齐位置、cross-attention Q/K/V 来源与融合点展示信息交换。
- **GNN / 时空模型**：显示图节点/边与消息传递轮次，或时间和空间两个轴的变化，避免把所有边都画成拥挤的线团。
- **生成、扩散、循环/检索模型**：通过时间轴、循环步进、状态/缓存更新展示迭代过程，按需演示两轮关键步骤。
- **非标准方法或非张量任务**：自主设计更适合其机制的二维过程图、空间坐标、状态机等；无意义的形状不得硬填。

**鼓励表现力**：用有语义的色彩、动效、分层景深、局部放大、过程对比、小型示意数据和自然语言注释让抽象计算可见；让模块输入与输出的变化能被“看见”，而不是旋转几个没有意义的方块。强制显示每种视觉编码的含义。若大小、长宽比、坐标或颜色并非真实数据比例，明确写“示意，不按比例”。对超过三维的张量展示选定轴的投影/切片，并始终保留**完整 shape 标签**。

## 3. 单文件、无需服务器、交互完整

- 生成一份能以 `file://` 直接打开的完整 HTML：样式写在 `<style>`，逻辑写在 `<script>`，形状/步骤/证据数据内嵌；无需 npm、构建工具、本地服务器或网络。**不能依赖 CDN、远程字体、外部图片、动态 import、fetch 本地 JSON 或远程 iframe。**
- 优先使用原生 HTML + CSS + SVG/Canvas；只有 3D 空间关系确实有助于理解时才用 Three.js/WebGL。采用库时须将可离线使用的库代码及必要许可声明一起合法地打包进同一个 HTML；做不到就退回原生实现，不得假称离线。
- **最小交互**：**从原始数据到最终训练/推理环节**的总览、当前步骤高亮、前一步/下一步、播放/暂停、重置；点击或键盘选中关键阶段展示数据形式、输入/输出 shape、操作意义和论文/代码位置。可按需提供训练/推理路径切换、速度调整、缩放、局部展开和循环轮次。
- 页面中有可阅读的**数据与维度流转表**：涵盖原始数据形式、加载与组织步骤、模型中间结果以及训练更新或推理输出（按实际存在的环节），列明数据结构、输入/输出 shape、语义、操作、来源及证据级别；重要未知量需显式说明。按钮要真正控制相应内容。
- 中文为主，保留关键英文术语。兼顾桌面与窄屏；文字要清晰、对比度足够，提供 `prefers-reduced-motion` 或显式关闭动画的方式，基本操作可用键盘完成。渲染大规模图时应使用聚合、按需展开或抽样，并清楚标明抽样。
- **安全与来源**：不要把论文或仓库中的不可信字符串作为未经转义的 HTML/JS 执行；不运行论文模型/训练脚本，不注入外部跟踪或请求。交互示意图不等于论文原图：原始 Figure/Table 仍从 `source/` 与 LaTeX 索引核对，不截图论文 PDF，也不伪造实际激活/数值。

## 4. 完成前验证、续读与降级

- 检查 HTML 在目标路径确实存在；能使用浏览器测试时以本地文件方式打开，实际触发前后步、播放/暂停、重置、模块详情和存在的模式切换，检查标签重叠、JavaScript 报错、离线资源以及窄屏表现。无法浏览器测试时，至少做静态结构/语法检查，并**明说尚未实际验证**。
- **从原始数据入口到最终环节**逐段复查动画/分支/shape；检查训练路径是否覆盖适用的监督、损失、反传和更新，推理路径是否覆盖适用的解码与后处理；核验来源、未知项、示意比例及训练/推理差异。复杂模型可以分层折叠细节，但不得删去关键阶段冒充完整流程。
- 在 `精读笔记.md` 记录 HTML 的相对路径、所覆盖的模型版本、可视化设计选择、核验结果和待解决问题。续读优先复用已有文件；如已被用户修改，不直接覆盖，需另存版本或保护性备份。
- 若环境无法创建文件或无法达到离线单文件要求，**说明具体限制**，仍在对话中呈现可核验的步骤与维度表；不把静态截图或联网网页冒充已完成的独立 HTML。
