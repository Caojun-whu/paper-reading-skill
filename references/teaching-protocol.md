# 渐进式论文精读教学协议

本指南服务于**讲懂一篇论文**，不是增加一个站点，也不替代论文与官方代码的证据核验。先在内部完整读懂材料，再将真实知识依赖拆成可被学习的最小单元。默认只在聊天里给用户当前需要的一小段，不要把内部详细检查清单全部输出。

## 0. 六站前先给整篇论文的知识地图

**首次精读或用户明确从头重读时，首轮单独输出简短的论文全景导读，讲完停下；「继续」才进入①动机。** 这是六站的前置概览，不是第七站，也不需要首轮讲完所有机制。「每轮一个核心问题」适用于随后六站；**全景导读是唯一常规例外**，只交代整篇逻辑。

导读默认用五个易扫读的标题：**一句话概括**（任务、方法、输出）、**要解决的问题**（主要瓶颈）、**核心方法**（真实的 2–3 项主要设计）、**主要实验发现**（1–2 项代表性结果及适用条件）、**核心贡献与证据边界**（贡献、局限、主张的支持程度）。背景元数据一两句即可，通常约 350–650 字；不提前抛出复杂公式、模块内部术语和完整实验表。

**证据严谨**：涉及实验数字必须核对论文 PDF 和原始 LaTeX 表，标明基线、指标与出处；未核实就明确写待核实，不抄其他 AI 总结，也不把「首次」「SOTA」宣传自动当成可靠结论。区分【论文】【官方代码】【分析】。导读结束给六站路线图，不额外创造编号。

随后每站先简短指出「本轮对应导读的哪个问题/设计」，使局部讲解始终有整体坐标，不反复粘贴导读。六站结束后**在⑥结尾**用「研究问题→两三项核心设计→实验支持→局限」重连整篇论文，而不是再加一个站。

**从头重读已有论文**：复用当前项目的 PDF、LaTeX、图表、代码；旧笔记作事实/问题参考，但旧站点进度不应阻止新的导读，新增内容保护人工修改。记录导读状态与下一站；若用户要求直接跳站或只要摘要，则尊重而非强制导读。

## 1. 六站的唯一任务与边界

| 站点 | 此站只建立的理解 | 暂不深入 |
| --- | --- | --- |
| ① 动机 | 问题、旧方法失败在哪里、作者切入点 | 架构和所有公式 |
| ② 方法总览 | 整体输入→核心思路→输出，关键模块的作用 | 具体字段、训练细节、逐模块公式 |
| ③ 数据 | 原始数据与单个数据对象的结构、字段及初步模型输入 | 完整 batch 计算、实验协议 |
| ④ 核心机制 | 逐个创新模块解决什么、怎样变换、为什么合理 | 端到端 batch 更新、所有 loss 的计算流程 |
| ⑤ 信息流与训练/推理 | 将③/④串起，一次 batch 更新或核心推理；HTML 显示真实运算 | 重复整段②–④与无关 downstream |
| ⑥ 实验与结果 | 实验问题、设置、结果、对主张的支持及局限 | 重讲整个方法结构 |

**每站开头先用一句话定位自己正在放大全景导读的哪部分**，但不重述整个导读。②第一次提到尚未认识的字段与术语，应以一句话解释其用途，明确「③/④会展开」，不能用术语堆出一整段技术报告。④模块设计解释是主角；⑤的运行与数值变化是主角，**前两站已讲清的内容使用指代与简短提醒，不再重新讲一遍**。

## 2. 一轮话只服务一个理解问题

默认采用以下节奏，按需要灵活调整表达，不强制机械标题：

- **问题**：例如「为什么需要两个编码分支？」而不是「下面完整介绍模型所有组件」。
- **直觉**：先用 2–4 句自然语言说清为什么要做这一步。
- **看见对象**：锚定同一个论文场景、③已认识的数据记录或原论文图里的一处，用小例子展示输入→变化→结果；不要频繁更换场景或擅自假设论文没给出的真实数值。
- **按需深入**：理解需要时才逐项拆公式和 shape；引入一个符号就说其语义、轴、单位、来源。用户明确要严谨推导可连续深入，不能以「少讲」为由省掉关键推导。
- **落点**：一句话说清本轮结论与上一问题的连接，再说下一小问题是什么。

一般一轮只新引入 1–3 个主要术语；首次出现的缩写给出中文解释与角色。复杂概念可以拆成几个相关回答；术语限制是默认防过载策略，**不是正确理解所需推导的硬上限**。

## 3. 看不懂时的恢复策略

当用户说「乱」「没懂」「先别往下」或回答暴露前提混淆：

1. 先定位是哪一个依赖断了：不认识输入对象？不理解某个中间量？不清楚为什么引入模块？还是不知道 loss 对谁优化？
2. **停在当前子问题**。用同一个数据对象换一个角度解释；优先有意义的图、极小数字或「不用该模块会怎样」的对比。
3. 如果前置概念欠缺，短暂回到③的数据或②的整体位置，补完后返回原站；不要把这种补缺当成自动跳站，也不要重启全部六站。
4. **不反复堆长答案**。在获得继续信号前不引出新的复杂分支，也不强制做考试式提问。

用户主动指定「展开数学」「看代码」「跳到实验」时按请求深入或跳转；不以默认三层为由阻止专家级讨论。

## 4. 「继续」与站内进度

每站可由多个小问题组成。**导读后的第一次「继续/下一步」进入①动机**；六站内部用户说「继续/下一步」时，优先处理**当前站下一未完成小问题**；本阶段的必要理解点都已经介绍过时，才切到下一站。说「下一站」或具体编号则直接跳转。站内小结可以一句话提示是否继续，但不需要每轮做强制理解测试。

`精读笔记.md` 在旧版文件上增量记录：**全景导读状态、两三项核心设计与代表实验出处、当前站、当前子问题、已清楚的概念、用户卡点、下一小问题**。如果笔记仍用老的③训练/④数据编号，读取时要根据内容迁移：旧④数据→新③数据，旧③训练的目标直觉归入④核心机制，loss/更新细节归入⑤信息流，不能凭旧数字误跳站；不要覆盖已有人工笔记。

## 5. 可视化与实验怎样配合教学

⑤站 HTML 仍要按 `references/flow-visualization-guide.md` 完成 batch 级真实动态计算、正确并行依赖、证据标记、单文件离线等验收。**但 HTML 是辅助学习而不是先于理解的入口**：每轮只聚焦已准备好的一个模块，先给读者一个低门槛解释，再使用其局部动画；不能一上来把所有 loss 和梯度扔给用户。

⑥站先一句话讲本篇实验究竟想检验哪些主张，再从一组最关键实验入手，解释所用数据/协议、baseline、指标和结果。后续小节逐个补消融、鲁棒性、效率等实际存在的实验。数据与原始表/图仍需逐项核验，但**核验全部材料不等于用户要在同一轮看到全部材料**。

## 6. 完成一段讲解前的自检

- [ ] 若为首次导读：是否有全局问题、2–3 项设计、核实的代表结果与贡献？未提前堆复杂公式？
- [ ] 若为六站内讲解：本轮只解决一个清楚的问题并回扣导读，没有无说明的新名词堆叠
- [ ] 用户知道现在讲的是完整方法中的哪一环，且理解了输入对象
- [ ] 直觉/示例先于复杂公式出现；复杂公式有逐步对应的解释
- [ ] 未把当前站和下一站的大量细节混在一起，也没有重复之前整站内容
- [ ] 关键事实可找到论文/代码依据，示意数值与真实值区别明显
- [ ] 最后一句说清了本轮要记住什么，以及下一小问题；六站完成后⑥结尾作整体回顾
